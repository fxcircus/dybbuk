# 04. UI, from the v3 canvas

**Source of truth: `Dybbuk UI v3.dc.html` in Claude Design project
`a3466a02-e100-482f-a5dc-0d9ad16fd4c4`.** Read it with the `DesignSync` tool
(`list_files`, then `get_file`), which needs a one-off `/design-login` from a
session that is not Remote Control.

The earlier spec in `inputs/04-ui-derived-from-text-spec.md` was derived from
the written description in `dybbuk-plan.md` section 2.7 when the canvas could
not be reached. It described a completely different interface (filled brass
knobs, a readout strip, a horizontal output slider) and has been replaced
wholesale. It is kept only as a record of what was guessed.

## 1. What the canvas is

A 900 x 620 plate: ink drawn on paper, not a panel with parts on it. Every
control is line art, so the whole window reads as one engraving.

- **Two sheets.** Dark (paper `#17150f`, ink `#ece8dc`) is the default; light
  is parchment (`#f2eee4` under `#1c1a15`). Red `#d45a4a` is the only other
  colour and it means heat: the danger zone, the lamp, the meters.
- **Three faces**, embedded as binary data so the plugin looks the same
  anywhere: EB Garamond for everything, Frank Ruhl Libre for the Hebrew
  wordmark, Pinyon Script for the patch name.
- **Grain and a vignette** over the whole plate, plus an inner keyline.

## 2. Layout

| Band | Contents |
|---|---|
| Header, y 0 to 52 | DYBBUK wordmark, Hebrew, the bypass diamond (reads IN or BYPASS), the patch name in script with step marks, the theme mark |
| Rule, y 62 | a hairline stopping 46 px short of each edge |
| Left and right edges | the IN and OUT trims: a solid ink rail with a hatched red meter climbing it and a hatched handle |
| Hero row, faces at y 174 | Time, Decay, Filter, Blend at 104 px, with the Sync diamond beside Time |
| Second row, faces at y 380 | Time Mod, Strength, the lamp with the clear stamp under it, Resonance, Absorb |
| Bottom, faces at y 535 | Agitate (red needle), the Loop/Gate rail, Speed |

## 3. The knob

Line art, not a filled arc: eleven index ticks around the travel, a knurled
rim of short ticks all the way round the face, dashed spokes at each limit, a
needle with a filled arrowhead, and the minimum and maximum named beside the
face. Nothing is shaded.

Decay carries a danger zone: past unity the index ticks go red, the space
between them is hatched red, and the whole face, needle and value turn red.
Time grows detents on its ring when Sync is on.

Drag is incremental at 220 px for the full range, 900 with shift held, so
pressing shift mid-drag cannot make the value jump. Double-click resets, and
on Decay it also empties the loop.

## 4. What the engine feeds it

| Published | Drawn as |
|---|---|
| loop energy | the lamp's brightness and swell |
| Decay past unity plus energy | the lamp's red shift and faster gutter |
| input and output peak | the two hatched meters, with peak holds |
| clears served | the stamp and the lamp flash on the acknowledgement, not the click |
| Time, Filter and Decay modulation | a red arc inside the face, from the needle to where modulation has taken it |

The lamp's flicker comes from the canvas (a decaying random walk with an
occasional gutter), but the level under it is the engine's real loop energy
rather than a guess from the knob positions.

## 5. Switching sheets

The canvas transitions its background over 350 ms. Fading only the paper would
read as a flicker here, because every line, letter and needle changes colour
too and they all swap instantly. So the whole plate cross-fades: a still of
the outgoing sheet is captured at 2x the moment the mark is clicked, the
colours switch underneath it, and the still dissolves over 350 ms on a
smoothstep, holding briefly before letting go. The overlay takes no mouse
clicks and its image is released as soon as it finishes.

`UISnapshot` catches the dissolve half way (`editor_snapshot_theme_fade.png`),
where both sheets' ink is visible at once, so the animation is reviewable and
not just asserted.

## 6. Knowing departures from the canvas

Each is a single line to reverse.

1. **Filter reads kHz here and integers in the DAW.** The canvas wants
   "3.0 kHz"; the CLAUDE.md readout rule says integers from 100 Hz up. The
   plate follows the canvas, the host string follows the house rule. This is
   the only place the two surfaces disagree.
2. **No em dash in Decay's readout.** The canvas has "1.12 — runaway"; house
   rules ban em dashes in UI copy, so it reads "1.12 runaway", in red.
3. **The modulation arc is drawn.** The canvas computes its geometry and then
   never renders it. It is drawn here, at the canvas's own radius, because the
   engine publishes the real thing and the plugin is worth watching while it
   modulates itself.
4. **Fourteen sync divisions, not nine.** The canvas lists nine and snaps to
   eight steps. The engine already had fourteen including triplets, which is
   more capable and already covered by tests.

The canvas has no Tones or Spread controls. Those parameters still exist,
automate and save; they simply have no knob on the plate.

## 7. One thing the canvas added

An **IN trim** on the left edge, alongside the existing Strength knob: IN sets
what reaches the plugin, Strength sets how hard that hits the loop. It is a
new parameter (`in`, -60 to +6 dB, hint 17, ahead of Bypass) applied once
before the dry split, so the dry path and the loop hear the same input and the
meter shows what the plugin is actually being fed.
